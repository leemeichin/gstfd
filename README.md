## My story. Your entire methodology.

I wanted an app that told me where to get lunch.

I put five restaurants in an array. I added a button. The button picked one. I ate a sandwich.

Read that again.

## The answer is a smaller fucking thing

You have an idea. Excellent. Somewhere inside it is one thing a person can actually do.

Build that.

A dashboard? Show the number that matters.

A marketplace? Let someone list a thing and someone else find it.

A lunch picker? I have extensive experience in this category.

The minimum viable product is the smallest version that delivers the promised result. A working button beats a forty-page meditation on buttons. The button must, however, do the thing. We are visionaries with standards.

## The five laws I discovered after lunch

1. **Pick the outcome.** Say what the user will be able to do in one sentence. That sentence is the meeting.
2. **Use what is already there.** Existing code, existing tools, existing patterns. My breakthrough technology was an array.
3. **Build the whole little thing.** Input to useful output. Finish that path before decorating the surrounding countryside.
4. **Try the actual thing.** Click the button. Run the command. See the result. A sandwich is a stronger signal than a sandwich roadmap.
5. **Stop when it works.** Deliver it, explain how to use it, and let the next need arrive in its own time.

Five laws. One case study. Absolute confidence.

## Install the mindset. It is one file.

The entire skill lives in [SKILL.md](SKILL.md). It is plain Markdown with a small YAML header. No runtime, dependencies, vendor SDK, or orchestration layer.

For an agent that supports `SKILL.md` skills, put it in that agent's documented skill location inside a folder named `gstfd`. For an agent that reads files, give it the file. For a chat-only agent, paste the contents into the conversation. The name of the model is between you and your accountant.

Then ask:

```text
Use gstfd from SKILL.md. Build me a lunch picker.
Choose the simplest useful MVP and get it working.
```

Replace “lunch picker” with your idea. This is the customization layer.

## What your agent actually does

It takes a quick look at the relevant code, chooses a small complete version, states a sensible assumption if needed, and builds. It checks the result at a depth appropriate to the work, then gives you the thing and the shortest useful explanation.

It spends its effort on the result. It does not generate a PRD, a sprint system, a committee of imaginary specialists, or a twelve-stage ceremony unless you asked for one.

Your explicit requirements still count. “Simple” describes the implementation, not a creative interpretation of your request.
